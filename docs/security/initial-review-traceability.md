# Initial security-review traceability

This matrix records evidence for the Milestone 1 threat model and the initial
security-review criteria in `FEATURES.md`. It is an audit aid, not a substitute
for the specification. A row is **covered** only when an enforcing production
boundary and an exact accepting and rejecting test exist. **Partial** means
useful enforcement or tests exist but the stated requirement is not completely
proved. **Deferred** identifies an acknowledged non-goal rather than missing
Milestone 1 behavior.

Test names below are executable names for C tests and pytest function names for
integration tests. All paths were checked when this matrix was written.

## Threat-model matrix

| Threat | Enforcing boundary | Accepting evidence | Rejecting/adversarial evidence | Status and remaining gap |
|---|---|---|---|---|
| Trusted issuer, wrong resource audience | `src/claims.c`: `audience_matches()` and `pg_oauth_claims_validate()` | `tests/claims_test.c`: valid string audience and valid audience-array cases; `tests/integration/test_oauth.py::test_valid_token_uses_normal_pg_ident_mapping` before policy reload | `tests/claims_test.c`: substring, empty array, duplicate and wrong-type audience cases; `test_valid_token_uses_normal_pg_ident_mapping` rejects the token after audience reload; Keycloak wrong-audience case in `tests/interop/keycloak/test_keycloak.py::test_keycloak_26_5_rfc9068_access_token_and_rejections` | **Covered** |
| ID-token or other JWT-type substitution | `src/jwt_envelope.c`: RFC 9068 type allowlist and opt-in missing-type policy in `pg_oauth_jwt_envelope_parse()` | `tests/jwt_envelope_test.c`: both RFC 9068 types; `tests/validator_test.c`: valid access token | `tests/jwt_envelope_test.c`: `JWT` and missing `typ` denied by default; `tests/integration/test_oauth.py`: missing-type exception still denies wrong type, wrong audience, and insufficient scope; Keycloak ID token in `test_keycloak_26_5_rfc9068_access_token_and_rejections` | **Partial**. The issuer's token kinds must have mutually exclusive audience/scope rules before missing-type mode is enabled. |
| Forged, unsigned, weakly signed, or algorithm-confused token | `src/jwt_envelope.c`, `src/jwks.c`, and `src/signature.c` | `tests/signature_test.c`: valid RS256 and ES256 signatures; `tests/jwks_test.c`: valid RSA and P-256 verification keys | `tests/jwt_envelope_test.c`: `none`, HS256 and disallowed algorithm; `tests/jwks_test.c`: undersized RSA, off-curve EC, algorithm mismatch, private material and non-signing keys; `tests/signature_test.c`: modified signature and wrong key | **Covered** |
| Stale keys, rotation, and attacker-selected `kid` | `src/issuer_key.c`, `src/cache_state.c`, `src/shared_cache.c`, and `src/jwks.c` | `tests/integration/test_oauth.py::test_local_idp_rotation_outage_and_recovery`: adopts key B and accepts A during overlap; `tests/issuer_key_test.c`: cached and refreshed selection cases | `test_local_idp_rotation_outage_and_recovery`: retired A rejected; `test_unknown_kid_refresh_is_suppressed_across_backends`: concurrent unknown IDs cause one refresh and remain denied; `tests/cache_state_test.c`: cooldown suppression | **Covered** |
| Expired or not-yet-valid token and skew boundaries | `src/claims.c`: NumericDate validation | `tests/claims_test.c`: valid temporal claims and token just inside expiry skew | `tests/claims_test.c`: expiry exactly at skew boundary, `nbf` beyond skew, and future `iat`; `tests/validator_test.c`: expired token | **Covered** |
| Stolen bearer token reused before expiry | No offline validator boundary can distinguish the legitimate holder from a thief | Valid short-lived token acceptance is exercised by `tests/validator_test.c` and the integration suite | None is possible for bearer-token replay without sender constraining, revocation, or introspection | **Deferred limitation**. Immediate revocation/introspection is outside Milestone 1; deployment TLS and short-lived-token guidance mitigate but do not eliminate this threat. |
| Valid principal assumes an unrelated PostgreSQL role | PostgreSQL applies exact identity matching or `map=`/`pg_ident.conf`; with delegation, `src/policy.c` requires a configured `role_claim` and `src/claims.c` checks the requested role | `test_valid_token_uses_normal_pg_ident_mapping` accepts the mapped role; `test_direct_identity_and_delegated_roles` accepts exact identity and authorized scalar/array roles | The same integration tests reject unmapped, unlisted, malformed, and HBA-disallowed roles; `tests/policy_test.c` rejects mismatched delegation settings | **Covered** |
| Ambiguous or mutable identity | `src/claims.c` requires `sub` and validates the selected claim; `src/identity.c` bounds and copies it directly; default `sub` is built in `src/config.c` | `tests/identity_test.c`: direct identity; `test_valid_token_uses_normal_pg_ident_mapping`: exact subject maps | `tests/claims_test.c`: missing, wrong-type and control-character subject and identity; `tests/identity_test.c`: empty, oversized and invalid input | **Partial**. Stability is an administrator/provider contract and cannot be inferred from token bytes. Provider-profile identity guidance remains deferred. |
| Malicious or compromised discovery/JWKS | `src/metadata.c`, `src/http_transport.c`, `src/jwks.c`, and exact issuer/host policies in `src/issuer_key.c` | `tests/metadata_test.c`: valid exact metadata; `tests/http_transport_test.c`: bounded trusted response; `tests/jwks_test.c`: valid signing keys | Unit rejection cases plus `tests/integration/test_oauth.py::test_local_idp_transport_failures_deny_and_recover`, which rejects hostile discovery/JWKS responses and proves recovery | **Covered** for hostile input and transport behavior. A correctly trusted but compromised issuer remains outside offline validation's protection. |
| SSRF, redirects, oversized responses, slow endpoints, and cache poisoning | `src/http_transport.c`, `src/http_freshness.c`, `src/cache_key.c`, and policy-separated shared cache | `tests/http_transport_test.c`: allowed host, trusted TLS, JSON response and freshness headers; `tests/cache_key_test.c`: complete canonical policy key | Component adversarial cases; callback transport failures/recovery in `test_local_idp_transport_failures_deny_and_recover`; trust-policy reload separation in `test_reload_separates_trust_policy_cache_entries` | **Covered** |
| Empty or incorrectly interpreted scopes | `src/policy.c` rejects empty required scopes; `src/claims.c`: strict `scope` string/array parsing and require-all comparison | `tests/claims_test.c`: valid scope string and array; `test_valid_token_uses_normal_pg_ident_mapping`: valid required scope | `tests/claims_test.c`: missing/insufficient/wrong syntax/duplicate scope and implicit `scp`; integration test rejects insufficient scope; `tests/policy_test.c` rejects empty required scopes | **Covered** |
| Provider-specific format applied to wrong issuer | `src/policy.c` accepts only policy `default`; `src/claims.c` rejects implicit `scp`; exact issuer validation is in `src/claims.c` and `src/metadata.c` | `tests/policy_test.c`: default policy; `tests/claims_test.c`: exact configured issuer | `tests/policy_test.c`: unknown policy; `tests/claims_test.c`: `scp` rejected and trailing-slash issuer mismatch | **Covered for current policy**. There is no provider-specific format selection. Future issuer-specific behavior needs separate review and issuer-binding tests. |
| Token, signature, secret, or sensitive claims disclosed in diagnostics | Stable error-code functions throughout `src/`; callback logging in `src/pg_oauth_validator.c` emits codes rather than token bytes | Successful real OAuth connection in `test_valid_token_uses_normal_pg_ident_mapping`; each unit boundary checks stable codes | `tests/integration/test_security_logging.py` uses distinct raw-token, signature, private-claim, response-body, and complete-token sentinels across normal and rejection paths while requiring stable diagnostic codes | **Covered** for validator-controlled diagnostics. PostgreSQL GUC values are explicitly not a secret-storage boundary. |
| DoS through repeated fetches or expensive JWT work | Token/document/key/count/time bounds in `src/jwt_envelope.c`, `src/http_transport.c`, `src/metadata.c`, `src/jwks.c`; refresh cooldown in `src/cache_state.c`/`src/shared_cache.c` | Boundary tests accept inputs within limits; robustness integration keeps valid cached authentication responsive during hostile load | Oversize/complexity unit cases; unknown-`kid` suppression; `tests/integration/test_robustness.py` exhausts all cache slots and applies bounded concurrent excess and mixed hostile/valid connection bursts | **Covered** by deterministic CI smoke bounds; longer performance profiling remains operational work, not an authorization acceptance gap. |

## Initial acceptance criteria

| Criterion from `FEATURES.md` | Exact evidence | Status / follow-up |
|---|---|---|
| Correctly signed token for another audience is rejected | `tests/claims_test.c` audience rejection cases; audience-reload rejection in `test_valid_token_uses_normal_pg_ident_mapping`; Keycloak wrong-audience rejection | **Covered** |
| Trusted issuer's ID token is rejected | `tests/validator_test.c` ID-token case; Keycloak ID-token connection rejection | **Covered** |
| Missing `iss`, `sub`, `exp`, `aud`, or configured identity is rejected | Enforcement is in `src/claims.c`; `tests/claims_test.c` has focused missing-claim cases for each mandatory claim and custom identity. | **Covered** |
| Wrong-type and malformed security-sensitive claims are rejected | `tests/claims_test.c` covers wrong-type issuer, audience, temporal, scope, and default/custom identity values; duplicate claims are rejected by `tests/jwt_envelope_test.c`. | **Covered** |
| Only administrator-allowed asymmetric algorithms and valid keys are accepted | `tests/policy_test.c`, `tests/jwt_envelope_test.c`, `tests/jwks_test.c`, and `tests/signature_test.c` positive and negative cases | **Covered** |
| Rotated keys are adopted without attacker-driven refresh storms | `test_local_idp_rotation_outage_and_recovery` plus `test_unknown_kid_refresh_is_suppressed_across_backends`; cache/issuer-key unit tests | **Covered** |
| Valid principal cannot assume an unrelated role | Direct, usermap, and delegated acceptance and denial in `test_valid_token_uses_normal_pg_ident_mapping` and `test_direct_identity_and_delegated_roles` | **Covered** |
| Delegation requires both validator and HBA policy | `tests/policy_test.c` and `test_direct_identity_and_delegated_roles` reject either setting alone, malformed role claims, and HBA-disallowed roles | **Covered** |
| No token or secret appears in normal, debug, or error logs | Multiple integration tests plus `test_security_logging.py` assert distinct token, signature, private-claim, and provider-response sentinels are absent while stable protected diagnostics remain present. Configuration explicitly forbids storing secrets in GUCs because PostgreSQL core may log changed values. | **Covered** for validator-controlled values and diagnostics. |
| Network failures and cache behavior are deterministic and documented | Local rotation/outage/freshness/recovery, hostile transport, unknown-`kid`, and reload-separation integration tests; cache unit tests; `docs/operations.md` and ADR 0002 | **Covered** |
| Negative tests cover the documented threat model and run in CI | `.github/workflows/ci.yml` runs `test-pg18` and `test-pg19`, which include `verify` and `integrationcheck` | **Covered** for the active offline suite. Keycloak interoperability is intentionally opt-in and remains a separate release gate. |
| PostgreSQL integration tests exercise real connections over TLS | Existing OAuth tests use TLS; `tests/integration/test_tls.py` proves libpq `verify-full` success and rejects PostgreSQL/provider hostname mismatch, untrusted CA, and deterministic already-expired leaf certificates on both majors. | **Covered**. |
