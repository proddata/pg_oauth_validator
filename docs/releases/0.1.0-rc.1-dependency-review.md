# 0.1.0-rc.1 dependency review

- **Review date:** 2026-08-08
- **Source revision:** `348b3aaf812d5f313c1e4c69b2f51d988f029607`
- **Candidate:** `0.1.0-rc.1` (proposed; not tagged or published)
- **Status:** **incomplete — publication blocked**

This record applies only to the source revision above. It records the evidence
available on the review date; it is not an approval to publish an artifact.

## Disposition

Do not create or promote release-candidate artifacts yet. The following items
block completion of the dependency review:

1. The release package does not yet carry the notices required for statically
   linked libjwt and Jansson. The package must preserve the applicable license
   notices and document how recipients can obtain the MPL-covered libjwt
   source corresponding to the binary.
2. Jansson and the dynamically linked OpenSSL and libcurl packages are
   installed without exact package-version or repository-snapshot pins. The
   PostgreSQL container digest therefore does not fully identify the build
   inputs after `apt-get update`.
3. Exact `dpkg-query` inventories were not captured for both PostgreSQL build
   environments. Debian and upstream advisory applicability cannot be signed
   off until those versions are known.
4. GitHub dependency alerts, code scanning, secret scanning, reviewer identity,
   and release approver identity remain to be recorded for the eventual tagged
   revision.

## PostgreSQL

PostgreSQL 18.4 is the current supported PostgreSQL 18 minor release. Its
2026-05-14 release includes security fixes including CVE-2026-6479,
CVE-2026-6473, and CVE-2026-6637. The pinned PostgreSQL 18 build reported
`18.4 (Debian 18.4-1.pgdg12+1)`, so it includes those fixes. PostgreSQL's
versioning policy recommends running the current minor release.

PostgreSQL 19 beta 2 was released on 2026-07-16. PostgreSQL explicitly states
that beta releases are not for production use and that details and APIs may
still change. PostgreSQL 19 packages are therefore compatibility-preview
artifacts only; they cannot be promoted as production-supported or relabeled
for PostgreSQL 19 final.

Primary evidence:

- [PostgreSQL 18.4 release notes](https://www.postgresql.org/docs/release/18.4/)

## libjwt

The build pins commit
`602118d99d46ca5df71bda60d3df642135417f29` (release 3.3.3) and verifies the
codeload archive with SHA-256
`47e3d5d00fd60141dbacbcb9a0c2e1b277740364ac1d15b50728dccb7afdf23c`.
The upstream commit is not signed; the checked archive digest is the current
integrity control and this provenance limitation must remain visible.

Release 3.3.3 fixes CVE-2026-44699 / GHSA-q843-6q5f-w55g, an RSA-JWK algorithm
confusion issue affecting 3.0.0 through 3.3.2. Release 3.3.0 had already fixed
CVE-2026-33996 / GHSA-ph96-hqpc-9f66. No unresolved upstream advisory was
identified for the pinned revision on the review date. The validator's own
asymmetric-only algorithm allowlist and strict key-type/algorithm checks remain
required defense-in-depth and are not delegated to libjwt defaults.

libjwt is MPL-2.0 licensed. Because its code is statically included in the
module, packaging review must add the required notice and a clear source-code
location or other compliant covered-source mechanism before publication.

## Jansson

The current build installs Debian's `libjansson-dev` without an exact version
or repository snapshot and statically embeds the result. An exact version must
not be inferred from the Debian release name; capture and enforce it before
completing this review.

Upstream Jansson 2.15.1 was current on the review date. The older disputed
CVE-2020-36325 applies through 2.13.1, but applicability to the actual candidate
cannot be closed until its exact package version is captured. Jansson's MIT
license and the separate notice for `src/dtoa.c` must accompany the statically
linked distribution.

Evidence:

- [Jansson releases](https://github.com/akheron/jansson/releases)
- [Jansson license](https://github.com/akheron/jansson/blob/v2.15.1/LICENSE)
- [Debian Jansson security tracker](https://security-tracker.debian.org/tracker/source-package/jansson)

## OpenSSL and libcurl

The module dynamically links the OpenSSL and libcurl supplied by its runtime
environment. Their exact Debian package revisions were not captured during
this review. No vulnerability disposition is asserted without that inventory.

The pinned base images are:

- PostgreSQL 18: `postgres:18-bookworm@sha256:882236b897e39051d2368c5ccc6cda944904723506b2dfc97f2a8f5bc9afa382`
- PostgreSQL 19: `postgres:19beta2-bookworm@sha256:9222211d932c983331df86f01a6224eba868d61000a334e4a3e613626cf884f0`

These digests do not pin packages subsequently selected from mutable apt
indexes. Before review completion, use a dated repository snapshot or enforce
exact package versions, capture `dpkg-query` and `pkg-config` output, inspect
the staged module with `ldd`, and review each exact version against both the
Debian tracker and upstream advisories.

Evidence sources for the follow-up:

- [Debian curl security tracker](https://security-tracker.debian.org/tracker/source-package/curl)
- [curl security advisories](https://curl.se/docs/security.html)
- [Debian OpenSSL security tracker](https://security-tracker.debian.org/tracker/source-package/openssl)
- [OpenSSL vulnerability index](https://openssl-library.org/news/vulnerabilities/)

## Required follow-up evidence

The next review revision must include:

- immutable repository/package inputs for both PostgreSQL build environments;
- exact package and `pkg-config` versions plus staged-module dynamic links;
- license/notice files present in the generated archives and their manifest;
- per-advisory applicability and disposition for the captured versions;
- successful strict tests, sanitizers, fuzz smoke, reproducibility checks, and
  install/rollback rehearsal from the reviewed revision;
- GitHub security results and named security reviewer/release approver.

Any dependency or package-input change invalidates applicable test and
reproducibility evidence and requires a fresh review record.
